# Проектирование

## Источники и преобразование

Полный инвентарь берётся из дерева одного SHA Karing sing. Итоговые SRS Karing авторитетны для сохранения объединений hiddify, MetaCubeX, Chocolate4U и российских источников. Готовый MRS допускается только при доказанной эквивалентности; совпадение имени недостаточно. Иначе SRS преобразуется с сохранением семантики. Неподдержанный файл может быть исключён только явным конфигом с точной причиной; ошибка сети, повреждение и неизвестные поля останавливают сборку.

## Имена и результат

Сохраняются регистр и значимые символы имён, без расширения srs; URL кодируются. Пространства имён отделяют geosite, geoip, ACL и остальные каталоги. Отдельный staging не заменяет старый output. Манифест учитывает каждый вход, выход, исключение и происхождение.

## Проверка и публикация

Pinned инструменты проверяются по хешам до запуска. Реальная offline-проверка всех providers выполняется в изолированном network namespace, при необходимости частями. CI проверяет целостность и соответствие текущему каталогу и SHA; исторический снимок проверяется независимо от текущего каталога. Публикация только прошедшего проверки снимка, orphan commit и force-with-lease по наблюдаемому SHA, без изменения main. Лицензионный gate не отключается.

Пользователь отдельно разрешил включение существующего `LICENSING_PROVENANCE_APPROVED` и публикацию, осознавая неподтверждённые upstream-права; фактическое включение и публикацию выполняет primary после проверок. Пользователь также разрешил явно перечисленные в manifest исключения непереносимых наборов целиком. Ошибки сети, контрольных сумм и повреждения остаются фатальными.

Предыдущий опубликованный снимок нельзя проверять тысячами GitHub API blob-запросов: следующая стадия CI должна использовать пакетный fetch зафиксированного SHA и безопасный архив с проверкой путей либо эквивалентный пакетный способ, без утечки авторизации на redirect.
